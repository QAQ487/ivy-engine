# Editor content hot reload

The Editor watches the open project's `rom/` recursively in Edit, viewport Play and fullscreen Play. It does not watch `resources/` and it does not create NTFS junctions into that tree. Changing an engine default requires an editor restart. Game DLLs continue to use the script reload queue. AI tools must build/deploy game DLLs; the Editor does not compile source files. Runtime/shipping builds, shaders and engine/API changes are excluded.

File notifications trigger background reconciliation. A periodic content audit recovers missed notifications, including changes that preserve file size and timestamp. A batch must remain unchanged for 500 ms. Project switching resets observation, and a busy scene loader retains later batches for subsequent frames. Asset Browser Refresh also requests reconciliation. Content paths are carried as UTF-8 (`PathFromUtf8` / `PathToUtf8` in `engine/core/utf8_path.h`, C++17/`u8path` and C++20/`u8string`); the monitor, asset index refresh, scene-asset scan, reload apply path, Asset Browser, model cache, and scene preload never build `std::filesystem::path` from UTF-8 via a narrow `std::string` ctor or call `path::string()` / `generic_string()` on user filenames. On Windows the dangerous direction is UTF-8 bytes passed to a narrow path constructor or `absolute(std::string)`: the runtime decodes those bytes as the process ACP, producing a wrong wide path and often `std::system_error` (the `engine_gui` content-apply `absolute(path)` site was the most likely crash for Explorer’s `hp_fill - 複製.png`). `path::string()` can throw only when a character is outside the ACP, so it is a secondary risk (ACP 932 can encode 複製). Index refresh and each change in a batch catch filesystem errors separately (log + Content Failure) so one bad path cannot drop the rest of an already-observed batch.

Loaded textures are replaced in their existing texture slot after decoding and GPU allocation succeed. IDs remain stable, sizes update, and engine billboard/particle/IBL consumers resolve the current SRV. Paths are normalized, including relative aliases and case differences. Cubemap changes refresh skybox/IBL references. An equirectangular PNG assigned as `skyboxCubemap` is rebaked into `rom/skybox/cache/` (stamp includes vertical FOV) and then reloaded through `CubemapReload`; files under that cache directory are cook output and do not reload the scene. Font atlases update in place, preserving pointers held by text renderers.

Changes requiring new objects use transactional scene preparation. This includes scene/Prefab/UI data, models, material-owned textures, audio, effects and gameplay DLLs. Successful Play reloads restart the current scene in its previous presentation mode; gameplay state can reset. Model candidates remain separate until old scene users are destroyed. Invalid scene JSON, referenced images or model candidates keep the previous scene. Unsaved Editor changes use the existing keep-Editor/load-disk conflict dialog. Deleted assets that are referenced by the current scene JSON, or still resident in a resource cache (textures/cubemaps, model SRV cache, `ModelAssetCache`, audio), leave existing resources alive and set the Content light to Failed (`Content removed; existing resources retained`). Deleting an unreferenced and unloaded file under `rom/` keeps the light at Watching and appends `Content removed (unreferenced, not loaded); watching: …` to the log. Scene JSON path matching is slash/case/`rom/`-prefix normalized via `engine/editor/content_removal_policy.h` (same rule as skipping an added file that the scene does not reference). References are not rewritten automatically.

The content indicator reports pending/success/failure; scene and script indicators retain detailed errors. Content diagnostics go to `content_hot_reload.log` in the project root and rotate by truncation at 1 MiB. Panorama skybox cook failures and coverage warnings use the same log. Scene timing diagnostics remain in `editor_scene_loading.log`.

## Validation

- Linux (no Windows): `./tools/run_content_removal_policy_check.sh` (or the `g++ -std=c++17 -I. tests/content_removal_policy_test.cpp` one-liner) — covers unreferenced remove → KeepWatching, scene-referenced → Failure, cache-loaded but not in scene → Failure, path normalization, and mixed batches.
- Linux (no Windows): `./tools/run_utf8_path_check.sh` (or `g++ -std=c++20 -I. tests/utf8_path_test.cpp`) — `PathFromUtf8`/`PathToUtf8` round-trip, safe-rom accept, `ResolveRomForRead`, and `ContentFileMonitor::Scan` for `hp_fill - 複製.png` and `測試.png`.
- Windows ACP regression: `tests/utf8_path_windows_check.cpp` (via `tools/run_content_reload_checks.cmd`, or the `cl` one-liner in that file’s header). Creates CJK temp files, round-trips helpers, scans with `ContentFileMonitor`, and asserts that `path(std::string utf8)` / `absolute(std::string)` mis-decode or throw when ACP ≠ UTF-8. On Linux the same source builds and prints `SKIP`.
- `tools/run_content_reload_checks.cmd`: content-removal policy, UTF-8/CJK path unit test, Windows ACP CJK check, content monitor (including CJK scan), and D3D11 WARP texture identity/size/SRV replacement/corrupt-file rollback.
- `tools/run_scene_hot_load_check.ps1`: actual Debug Editor host with temporary scenes; checks scene/Canvas/settings rollback, unsaved conflicts, viewport/fullscreen automatic Play restart, DLL failure/recovery, automatic asset indexing, 20 live texture replacements, invalid textures, new texture references and Prefab edits. It restores the original scene and removes successful asset fixtures.
- `tools/run_2d_regression_checks.cmd`: existing focused engine regressions.

The host check starts from the most recently opened project. Do not run it while another Editor is editing that same project. Automated host evidence does not replace visual acceptance of every asset format in the game. One Editor restart is required to load this engine-side implementation; later supported content changes use hot reload.

## Verified delivery evidence (2026-10-25)

Debug Editor build and the existing 2D regression suite pass. The actual Editor host opened Village & Goblin, passed all scene/texture/Prefab/model scenarios, and restored its original scene. Twenty live texture replacements across viewport/fullscreen Play measured a maximum of 1.033 seconds. D3D11 WARP tests also passed font pointer/atlas-ID preservation and invalid-font rollback.

Sound/effect/material/animation-specific interactive acceptance and manual visual acceptance of the complete game remain unverified. Their content routes are implemented; these automated results must not be described as proof of every format's appearance or sound.
